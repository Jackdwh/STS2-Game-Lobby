# 名册可靠性与 0.113 模式补齐（v0.6.3-beta113.2）

本轮只实现用户指定的最高优先级和第二优先级，在 `fix/beta-0.113.0-compat` 的 `bc43886` 基础上追加，作为本 Fork 的 `v0.6.3-beta113.2` 预发布内容；不覆盖已有的 `v0.6.3-beta113.1`。

## 1. Tail 名册减员同步

- 复用原生可靠 `PlayerLeftMessage`，未增加 wire 消息类型、消息编号或服务端字段。
- 房主在绑定的 ENet 发送入口识别原生离开消息，客机在现有分发入口使用实际传输对端、通道和活动绑定校验授权。不能只靠报文声称的 senderId 获取房主权限。
- 经过授权的离开事件只移除对应成员，保留剩余真实槽位；重复广播/重复通知幂等，不使用 `Reset()`。
- 原生离开增量不额外消耗完整快照 revision，两端更新同一名册基线，后续完整快照仍执行原有版本与成员/槽位校验。
- 缓冲消息保留其原始传输上下文，释放时才应用减员；插入矩阵消息与其扩展帧之间的离开消息仍拒绝。
- 已验证消息的重放豁免只适用于同一条消息、同一总线，避免回调中嵌套消息绕过授权。
- 原生对局中的离开通知仍正常交给游戏处理，但不会从用于重连的存档角色名册中删除角色。大厅与对局语义分开。
- 保留内部仅剩房主的中间态，不扩大既有 2..8 的完整 wire 名册约束，不新增单人 Tail 开局功能。

## 2. 续档乱序接管

`RestoreLoadJoinPlayers` 不再把加入顺序等同于存档槽位顺序，改为核对：

- 人数一致且玩家 ID 唯一；
- 玩家身份集合完全一致；
- 载体 ID、解码位数与存档下标/真实槽位一致。

随后按名册的规范槽位顺序恢复消息；校验成功后才提交名册状态。多余、缺失、重复、未知身份、错误槽位仍拒绝。

**不改变角色继承规则**：新玩家仍可选择空闲存档角色，用该角色的存档 NetId 加入，不要求原玩家本人回来。原有服务器槽位占用、踢人权限、工单与重连 nonce 机制保留。

## 3. 模式与续档一致性

- 保存模式解析优先使用新版 `GameMode` / `IsCustomGame`，保留缺少这些成员时的旧版回退。
- 空修改器的自定义存档仍路由到自定义载入页；Blitz/Dread 不会仅因存在修改器被误认为自定义。
- LAN 模式选择器与大厅建房选择器增加极速/恐惧，使用游戏自身按钮的解锁状态；缺少原生模式或按钮时不可用，不自动解锁。
- UI 选择 ID 与游戏枚举值分开，按名称解析新版枚举，避免 Blitz/Dread 数值错配。
- 房间卡片与模式标签正确显示极速/恐惧，不再落为 STD；主客页面解析复用同一模式辅助方法。

## 4. 放弃存档结果处理

- 兼容旧的 void API 和新的 `PostRunProgressUpdateResult.success`。
- false 解释为“本次进度更新未应用”，不是直接认定磁盘写入失败；0.113 的一个实际原因是存档没有本机玩家。
- 未应用或抛出异常时增加日志和完成提示，保留先确认、先备份再放弃的行为，不强行计入进度，不取消用户已经确认的放弃意图。
- 自动测试使用替身对象核对结果与异常传播，不执行真实用户存档删除。

## 验证结果

- 两个最初的真实消息复现用例均先失败：乱序读档被拒、减员后开局被拒；修复后通过。
- 另一个嵌套消息授权用例先复现原重放豁免的问题，收窄到具体消息/总线后通过。
- 全量客户端单测串行：**1316 通过，1 项既有跳过，0 失败**。
- 协议计划测试：**11 通过，0 失败**。
- 核心协议、重开、新模式及相关界面测试合跑：**112 通过，1 失败，共 113 项**。
- 唯一失败仍为此前已存在的 `Create_dialog_wraps_its_content_instead_of_filling_the_viewport`：卡片与内容高度差 102，断言上限 100。未放宽断言或将它计为通过。
- 模式选择器测试补上独立 1280×720 视口，五个选项与原生可用性测试通过；没有通过降低原宽度断言掩盖问题。
- 类型加载：**1246 个类型通过**。

覆盖包括：三人/稀疏槽位减员后开局、同角色替补与新 nonce、重复广播、伪造/错误通道/无上下文/删除房主拒绝、缓冲释放、配对屏障、对局中角色保留、乱序接管及负向身份/槽位案例、模式映射、原生解锁和新旧进度返回值。

## 实机与发布边界

- 本轮尚未完成三人以上或多设备实机验证，自动化通过不等于全部平台/模式/MOD 组合通过。
- 测试两个 Tail 修复时，**房主与客机都应使用这一候选包**。没有新增 wire 格式，不代表未升级的旧客户端也已获得名册行为修复。
- 服务端 API/DTO 没变，本轮没有修改大厅服务端或注册服务。
- 不包含结算页新开一局、跨局 BoundSaveKey 转换、自动解锁、隐藏兼容协议或复用连接原地重开。
- 原有桌面重开空服务保护保留；没有重新加入临时诊断探针。
